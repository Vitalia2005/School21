* **Объяснение выбора маршрута:** Маршрутизатор в Linux руководствуется правилом Longest Match Prefix — совпадение по наиболее длинной маске сети. Так как маска подсети `/18` длиннее (точнее) маски маршрута по умолчанию `/0`, пакеты в локальную сеть уходят напрямую через интерфейс, минуя шлюз.

### 5.5. Построение списка маршрутизаторов
* Вывод утилиты `traceroute` от ws11 до ws21 и параллельный дамп `tcpdump` на r1:
  ![Вывод ](screenshots/Screenshot 2026-07-09 035523.png)
* **Принцип работы traceroute:** Утилита отправляет пакеты с последовательным увеличением значения TTL (1, 2, 3...). Каждый транзитный узел уменьшает TTL на единицу. При TTL=0 роутер отбрасывает пакет и генерирует ICMP-сообщение типа 11 (Time Exceeded), возвращая его отправителю. По адресам этих ответов traceroute поэтапно определяет структуру пути.

В этом пункте были использованы следующие основные опции и директивы DHCP-сервера:

subnet ... netmask ... — задает подсеть и маску, в пределах которой работает DHCP-сервер.

range — определяет диапазон динамических IP-адресов, доступных для свободной выдачи клиентам.

option routers — указывает адрес шлюза по умолчанию (Default Gateway) для клиентов.

option domain-name-servers — передает клиентам адреса DNS-серверов (в нашем случае 8.8.8.8).

host [имя] — директива объявления статического хоста для фиксированной выдачи параметров.

hardware ethernet — опция, указывающая конкретный физический MAC-адрес сетевой карты клиента, по которому сервер его идентифицирует.

fixed-address — жестко закрепляет конкретный IP-адрес за указанным выше MAC-адресом, исключая его из общей динамической раздачи.

### 2. Базовый фаервол на r2 (Запрет FORWARD)
Создала скрипт фаервола на **r2** со следующими правилами:
1) Удаление правил в таблице filter — `iptables -F`
2) Удаление правил в таблице NAT — `iptables -F -t nat`
3) Отбрасывать все маршрутизируемые пакеты — `iptables --policy FORWARD DROP`
